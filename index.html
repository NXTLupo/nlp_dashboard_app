Open-source text analysis · FastAPI

NLP Dashboard

An analyst puts a folder of PDFs, Word files, text, CSV and JSON into one ZIP, uploads it, and gets a single page with paragraph sentiment, a short machine-written summary, topic phrases and a word chart where each word opens the paragraphs it came from.

SentimentDistilBERT SST-2, scored per paragraph
SummariesDistilBART CNN on 800-character chunks
Topics and wordsscikit-learn NMF, NLTK word counts
Runs onFastAPI and Plotly.js, no API keys
Upload

What happens to an uploaded file

The upload form posts one ZIP to POST /zip. The router extracts five file types, and a reader chosen by file extension turns each file into a list of paragraphs before any model sees the text.

Models

Which model produces each result

NLPPipeline.process() hands the cleaned paragraphs to four producers. Sentiment is scored per paragraph. The summarizer and the topic modeler each run once per file and again on all files combined, and the word counts cover the combined text only.

Long paragraphs are split before scoring

SentimentAnalyzer tokenizes each paragraph first. Past 512 tokens it scores 256-token pieces, averages their polarity and keeps the most common label.

The summary headings come from keywords

The first three chunk summaries become Key Findings. Chunks that mention words such as "impact" or "result" feed Implications, and chunks with "should" or "recommend" feed Recommendations once the text runs past two chunks.

Topic phrases are joined terms

Each NMF component contributes its four highest-weighted terms, joined with spaces. The features include two- and three-word n-grams, so a phrase can repeat words, as "new new payee payee add" does.

Dashboard

How the results reach the charts and the word modal

POST /zip runs the whole pipeline inside the request, stores the output in a module-level dict and answers with a 303 redirect. The browser's GET /dashboard then reads that dict, scores every topic and word a second time with TextBlob, and sends one HTML page with the chart data embedded as JSON.

Run it

Run it locally on Python 3.11

The pinned numpy==1.26.3 and torch==2.2.0 have no wheels for Python 3.13. In the README's test on Windows, a fresh install of requirements.txt came to about 1.8 GB, most of it PyTorch.

Set upPython 3.11
git clone https://github.com/NXTLupo/nlp_dashboard_app.git
cd nlp_dashboard_app
python3.11 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
Runthen open 127.0.0.1:8000
# from the repository root: main.py mounts app/static by relative path
uvicorn app.main:app --reload
# upload docs/readme/sample_corpus.zip on the page, then:
curl http://127.0.0.1:8000/analysis-results
curl -X DELETE http://127.0.0.1:8000/clear-results
The first upload downloads the models

On the first upload, transformers fetches DistilBERT (about 256 MB) and DistilBART (about 1.2 GB) into the Hugging Face cache, and NLTK fetches its tokenizer and stopword data. With the models cached, the README's test run took about 25 seconds on CPU.

Document text stays on your machine

The app needs no API keys. Its outbound requests go to the Hugging Face Hub and the NLTK data server for model files, and the browser loads Plotly.js from cdn.plot.ly, so the charts need an internet connection.

Known limits

The app holds one analysis in memory for every visitor and loses it on restart. The page title and card headings describe AI and financial crime for any corpus. As shipped, POST /run-pipeline and GET /results return 500, and GET /download-results returns a URL that 404s.
